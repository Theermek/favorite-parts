# TASK: Поиск автозапчастей и аналогов (Favorit Parts API)

## Цель
Клиентское приложение на React для двухэтапного подбора запчастей:
1. Ввод артикула → список производителей (брендов).
2. Выбор бренда → таблица детали и её аналогов с предложениями.

Документация API: https://lk.favorit-parts.ru/static/wsprice.pdf

## Стек (строго)
- React + Vite, **JavaScript (без TypeScript)**
- Redux через **Redux Toolkit** (официальный рекомендуемый способ писать Redux) + react-redux
- Bootstrap (только CSS, без react-bootstrap)
- Запросы через нативный `fetch`, без axios

## Главный принцип: максимальная простота
- **Никаких лишних библиотек.** Разрешены только: `react`, `react-dom`, `@reduxjs/toolkit`, `react-redux`, `bootstrap`. Любую новую зависимость согласовывать.
- Без роутинга, без TS, без UI-китов, без RTK Query, без лишних абстракций.
- Простой, читаемый код важнее «умного». Одна страница.

## API
`GET http://api.favorit-parts.ru/hs/hsprice/?key=...&number=...[&brand=...&analogues=on]`

- Этап 1: `number` → берём **уникальные бренды** из `goods`.
- Этап 2: `number` + `brand` + `analogues=on` → сам товар + `analogues[]`.
- `number` и `brand` кодировать через `encodeURIComponent` (бренды вида `NGK/NTK`).

### Особенности ответа (обязательно обработать)
- **Цена — только из `warehouses[].price`.** Поле `goods.price` не использовать (устарело по доке).
- **Ошибка:** приходит `{ "error": "..." }` вместо `goods` (возможно с HTTP 200).
- **Не найдено:** не пустой массив, а один элемент-пустышка с `goodsID = "00000000-0000-0000-0000-000000000000"` → показывать «ничего не найдено».
- **Нет в наличии:** `count: 0`, `warehouses: []` → строка с пометкой «нет в наличии».
- **Сбой сети:** ловить в `catch`, показывать понятное сообщение.

## Безопасность и CORS
- Ключ хранится в `.env` (`.env` в `.gitignore`, в репо — `.env.example`).
- Запросы идут через **proxy в `vite.config.js`**: он решает CORS и подставляет ключ, ключ не попадает в клиентский код.
- В README указать: в проде ключ должен жить на сервере.

## Отображение
Таблица: **одна строка = одно предложение (товар × склад)**.
Обязательные колонки: **Название, Производитель, Цена, Остаток**.
Желательно: артикул, склад, дата отгрузки.

## Состояния UI
Для каждого этапа отдельно: `idle | loading | succeeded | failed`.
- Лоадер (Bootstrap spinner)
- Ошибка (Bootstrap alert)
- Пусто («ничего не найдено»)
- Новый поиск сбрасывает выбранный бренд и таблицу.
- Учитывать гонки: ответ устаревшего запроса не должен перезаписывать новый.
